# EtherLex: working notes

Premium, smooth, desktop-first Flutter companion for Canvas LMS. Windows first. Package `etherlex`, app name in `lib/app/app_info.dart`.

## Commands
- Flutter is pinned to **3.47.8** (`environment.flutter` in pubspec, CI and release workflows). 3.50.0 loses the GPU context while pdfrx decodes page images (flutter/flutter#196618); remove the pin only after that is fixed and PDF scrolling is verified. Note 3.47 has no `ScrollCacheExtent`: use `cacheExtent`.
- `flutter pub get` after any pubspec change
- `dart run build_runner build --delete-conflicting-outputs` after any Drift schema change (schema is v3)
- `flutter analyze` and `flutter test` must both be clean before a change is done
- `flutter run -d windows --profile` to judge smoothness (debug mode is not representative). F9 toggles the perf overlay.

## Architecture
- Feature-first: `lib/features/<feature>/{domain,data,presentation}`. Shared code in `lib/core`, widgets and tokens in `lib/design_system`.
- UI reads local Drift streams or cached data; repositories write them. Sample mode uses in-memory mock repositories (`Mock*Repository`), real mode uses `Canvas*Repository`. Every repository interface needs both.
- Riverpod 3 (Notifier, AsyncNotifier, StreamProvider). Routing: go_router ShellRoute. HTTP: Dio through `CanvasClient`. DB: one Drift file per Canvas host (`AppDatabase.forAccount`).
- Everything EtherLex writes lives in `%APPDATA%/EtherLex/`, keyed by account scope (`core/storage/account_scope.dart`; old host-named data is adopted by the first account, nothing is deleted on sign-out or update):
  - `settings/<scope>.json`: courses, hidden folders, notifications, grade plans, AI consent, how long chats are kept (`chatRetention`: always, month, session; `chatsToSave` decides what is written, `chatsToShow` what stays on screen), how each page was left (`viewPrefs`: All/Starred, folded groups, the Activity filter, the last Files folder; `viewPrefsProvider`, the calendar always opens on this week) (`FileSettingsStore.forScope`). Notifiers must `ref.watch(settingsStoreProvider)` (`features/settings/presentation/settings_store_provider.dart`) and ignore loads from a stale store.
  - Every JSON file goes through `core/storage/json_file.dart` (`JsonFile`: writes to one path are queued and atomic, damaged files read as null). File names use `cleanScope`.
  - `ai/<scope>.json`: AI service, model names, OpenAI-compatible address (`AiSettingsStore`). `chats/<scope>.json`: conversations (`ChatStore`).
  - `files/<scope>/` offline copies (LRU; the limit is per account, 1/3/5/10 GB, `offlineLimitGb` in the settings file; sizes are counted in an isolate, `offlineUsageProvider`) and `file_index/<scope>/` saved listings. All file access goes through `FilesRepository.localPath`.
  - App-wide: `appearance.json` (theme, typeface, palette, background pattern, collapsed sidebar), `updates.json` (update check).
  - One Drift database per account (`AppDatabase.forAccount`).
- Downloads go where Settings > Files & downloads says (`downloadPrefsProvider`, `downloads` in the settings file): the folder Windows reports as Downloads (`windowsDownloadsFolder`, asked from the runner with `SHGetKnownFolderPath`), a chosen folder, a course subfolder, or a Save dialog. Never inside `%APPDATA%/EtherLex` (`isAllowedDownloadDir`). All downloads go through `downloadWithToast`.
- Secrets: the Canvas token and the AI keys (per account and service) are in flutter_secure_storage (Windows credential store), never in the JSON files.

## Design system
- New look ("Oleafly feel"): dotted canvas, flat surfaces with hairlines, violet accent, handwritten Ink Free (Windows font, falls back to Segoe Print then Inter) or clean Inter, light and dark.
- Tokens: `design_system/theme/ether_colors.dart` (EtherColors.light/dark), `ether_text.dart`, `ether_theme.dart`. Read them with `context.colors` and `context.text`; never hard-code colours. Text colours (and `accent` as link text) reach 4.5:1 on canvas, surface and sunken in every palette and mode; anything filled behind white text uses `accentFill` / `dangerFill`, never `accent` / `danger` (`test/accent_palette_test.dart` checks it). Colours that mark a kind of thing and stay the same in every theme (file types, activity kinds, the close button) live in `theme/fixed_colors.dart`, course colours in `course_palette.dart`.
- Components: `design_system/ether/` (ETap for hover/focus/press, `focusable: false` for rows the page drives with its own cursor; ESpin, EIconButton, EButton, ESearchTrigger, ESwatch, DotGrid, showEtherDialog/EDialog/confirmAction, menu styles). Icons only via `EIcons` (Lucide).
- Shell: sidebar (wide windows) or floating icon rail (under 1080 px, or any width after Ctrl+B / the collapse button, remembered). `app/shell/nav_tools.dart` pins Settings, shortcuts, help, the theme toggle and collapse under the navigation (the rail shows Settings, theme, expand). The title bar holds brand, search and the avatar; the avatar menu is account only.
- List screens: `design_system/ether/list.dart` (EPageHeader, ESyncButton, ESegmented, EGroupHeader, ESectionLabel, ECheck, EStar, EEmptyState, EErrorState, ESkeletonList) and `detail_pane.dart` (details beside the list from 860 px of content width, a dialog below that). Selection = keyboard cursor = what the pane shows; Esc clears it.
- Settings (Ctrl+,): a dialog with a searchable sidebar of sections (`features/settings`). Every entry is a `SettingsItem` in `settings_sections.dart` (section, search text, builder), drawn as a `SettingsRow` (title, one-line description, control on the right) or a `SettingsBanner`. New settings go there, with keywords, so search finds them. "Reset to defaults" per section is `settingsResets`: it never touches the token, API keys, permissions, grade plans, chats or offline files. `showSettings(context, section: ...)` opens a section directly.
- Appearance (theme, typeface, accent palette, background pattern dots/grid/plain) is app-wide; Settings > Appearance shows the choices as `EOptionCards` (`design_system/ether/option_cards.dart`), the one place to change them besides the sun/moon button and Ctrl+K: `%APPDATA%/EtherLex/appearance.json`, `appearanceProvider`.
- One running copy per install folder: the runner holds a session mutex named after the program path (`ClaimSingleInstance` in `windows/runner/main.cpp`); a second launch brings the first window forward and quits. A dev build and the installed app do not block each other.
- Window: our own title bar, no native caption. The runner (`windows/runner/window_frame.cpp`) removes the caption in `WM_NCCALCSIZE` and answers `WM_NCHITTEST` for the top resize edge and the maximise button (`HTMAXBUTTON`, which gives Snap Layouts); no layered window, no DWM frame extension. Dart talks to it over the `etherlex/window` channel (`WindowControl` in `app/window/window_chrome.dart`). No window_manager/nativeapi: their custom frame made every resize step slow on the raster thread. `ETHERLEX_NATIVE_FRAME=1` (environment variable) brings the native caption back for comparisons. Other diagnostic switches: `core/diag.dart`, and `ETHERLEX_DIAG_MESSAGES=1` (environment variable) to log window messages around each click to `etherlex-messages.log` next to the program.
- Pages stand on a transparent `ColoredBox` (`_floor` in `app/router.dart`): a tap that hits nothing in a page would reach the route's modal barrier, which plays the system alert (the Windows ding).
- Renderer: Skia, not Impeller (`set_impeller_switch(Disabled)` in `windows/runner/main.cpp`). With Impeller, live resizing lagged even with the native frame; Skia is smooth. Flutter will remove this opt-out at some point: after each Flutter upgrade, compare resizing with `flutter run -d windows --profile --enable-impeller`.

## Rules
- Do not add `BackdropFilter` to dialogs. Use `SmoothScrollController` for lists.
- Dart raw strings cannot contain `\'`: use triple-quoted raw strings for regexes with both quote kinds.
- Lints: use null-aware elements (`?value`) instead of `if (x != null) x`.
- Add a test for every piece of pure logic (parsing, grade maths, alerts, cache). Files in `test/` mirror the feature.
- The assistant never changes anything itself. It proposes in `etherlex-plan` / `etherlex-actions` / `etherlex-courses` / `etherlex-files` / `etherlex-submit` / `etherlex-lookup` code blocks (`grades/domain/plan_proposal.dart`, `chat/domain/proposed_actions.dart`, `proposed_courses.dart`, `proposed_files.dart`, `proposed_submit.dart`, `proposed_lookup.dart`), strictly parsed, shown as cards; nothing happens without Apply and every change has Undo. Marking done warns and confirms. It may estimate only what does not touch real grades (the letter curve, item counts), flagged in `guessed` and shown on the card as a guess; weights, categories, ids, done and hiding are never guessed. Settings it may propose are listed in `chat/domain/proposed_settings.dart` (no keys, sign-out or updates). It cannot submit work: submissions would need their own explicit consent step.
- Security: the Canvas token goes only to the same origin (https, host, port; `isSameOrigin`), redirects on tokened downloads are followed by hand (`redirectTarget`), the AI server address must be https except for localhost (`isAllowedAiBaseUrl`), Office files are read with the system `tar` by full path with size caps, files that can run code are only revealed and web pages ask first (`openSafetyOf`; open from UI with `openWithCare`), and every file EtherLex saves or opens is marked as downloaded from the internet (`markFromInternet`, so Office uses Protected View). Updates are checked against a SHA-256 from the same release but are not code-signed (known limit).
- Only the user's own data and the Canvas API are touched, plus the public GitHub Releases of this repo for the update check (`features/update`; nothing about the user is sent; it can be switched off in Settings), plus the AI service the user chose for the assistant (their own API key). That service receives what the user types and only what they attach from Canvas (assignments, grades, announcements, files, pictures), after a one-time consent per service and account, tied to the server for the OpenAI-compatible service (`consentKeyFor`, `ai_consent.dart`; changing the server asks again, and changing it while a key is saved asks before the key goes there); attachments are never added automatically. Never log tokens or API keys.
